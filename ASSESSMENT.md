## Agent Handoff

Read on every Class 2+ task.

- Browser data access is read-only in all cases. This is a hard rule in [AGENTS.md](AGENTS.md), not a preference. Firefox proves it with a hash comparison in `tests/test_firefox.py`.
- Nothing below `src/bookmark_exporter/ui/` may import Qt. See ADR-003. Breaking this makes the suite unrunnable without a display and kills FU-002.
- The Qt background-task code has a trap that has already bitten once: `QThreadPool` owns the `QRunnable`, but not the Python signal object, so `MainWindow` must keep a reference to each in-flight task. Symptom when broken is `RuntimeError: Signal source has been deleted` on stderr while tests still pass. See src/bookmark_exporter/ui/main_window.py:44-74.
- Safari code paths are unverified. Do not report Safari as working. See [VALIDATION.md](VALIDATION.md).
- Test fixtures are synthetic and must stay that way. No real bookmark exports, profile paths, or personal URLs.
- `tests/test_ui.py` needs `QT_QPA_PLATFORM=offscreen` where there is no display, and skips when PySide6 is absent.
- The build brief in `prompts/` is not agreed scope. There is no contractual authority at this tier.

## Known Issues and Risks

- **Safari is unverified.** The provider is isolated and discovery contains provider failures, so the risk is confined to Safari being wrong rather than the application breaking. Still, it should not be described as working.
- **Chromium bookmark JSON is undocumented and version-dependent.** Handled defensively: unknown node types, wrong types, and missing keys are skipped per record, and recursion is bounded. A browser format change would degrade to missing bookmarks rather than a crash.
- **Firefox schema assumptions.** `build_tree` depends on the `moz_bookmarks` guid constants and the type codes. A schema change would surface as a corrupt-data error, which is visible rather than silent.
- **UI wiring is thinly tested.** See TD-001.
